## 문제 상황

- AI 에이전트에 구현을 맡기기 전, 계획 단계에서 한 번에 10개가량의 질문을 하도록 했습니다. 각 질문마다 번호에 맞춰 답을 직접 입력해야 했습니다.
- 병렬 세션을 오가며 작업하다 보니, 세션에 돌아올 때마다 그 세션이 무엇을 하던 중이었는지 파악하기 위해 대화를 다시 읽어야 했습니다.

## 접근 방식

![Sidecar 요약과 작업 그림 화면](/portfolio/sidecar-summary.png) ![Sidecar 작동 방식](/portfolio/sidecar-how-it-works.png)

<small>왼쪽: 세션 요약과 작업 현황 화면, 오른쪽: 작동 방식</small>

- 답변 종료 hook에서 질문과 선택지를 추출해 **패널에 버튼으로 표시**했습니다.
- 모델이 만든 선택지가 그대로 사용자 프롬프트로 들어가므로 전송 전에 보이지 않는 문자를 제거했습니다.
- **3턴마다 현재 대화를 fork해** 목표, 현재 작업, 결정, 남은 작업을 요약하고, 세션 시작 시점의 git 상태와 비교한 변경 파일을 함께 보여 줬습니다.

## 해결 및 성과

- 질문 번호와 답을 직접 입력하던 방식을 버튼 선택 후 일괄 전송으로 바꿨습니다.
- 다른 세션에서 돌아왔을 때 **대부분 요약만으로 작업을 재개**할 수 있었고, 맥락이 부족한 경우에만 이전 대화를 확인했습니다.
- 합방 프로젝트 **팀원 3명**에게 공유했고, 사용한 팀원은 편리하다는 피드백과 함께 지속적으로 사용했습니다.
