## 문제 상황

[grilling 스킬](https://github.com/mattpocock/skills)을 활용한 개발 사이클에서 한 번에 10개가량의 질문을 받고, 질문 번호에 맞춰 답을 직접 입력해야 했습니다. 또한 여러 Claude Code 세션을 오가며 개발하다보면 해당 세션이 어떤 작업을 하고 있었는지 파악하기 위해 대화를 다시 읽어야 했습니다.

## 접근 방식

![Sidecar 질문 버튼 화면](/portfolio/sidecar-demo-still.png) ![Sidecar 요약과 작업 그림 화면](/portfolio/sidecar-summary.png)

왼쪽: 질문별 선택지를 버튼으로 표시하고 답변을 일괄 전송하는 화면, 오른쪽: 세션 요약과 작업 현황 화면

- 질문 번호와 답을 직접 맞춰가며 입력하는 수고를 줄이기 위해, Claude Code hook 이벤트에서 질문과 선택지를 추출하고 패널에 버튼으로 표시했습니다.
- 제 Claude Code 대화 기록에서 2,381개의 모델 답변을 기준으로 파서를 적용해 인식 규칙을 검증했습니다. 숫자 제목(`### 1. 결과`)까지 선택지로 인식하도록 넓혔을 때는, 인식된 항목 대부분이 질문이 아닌 보고서의 절 제목이어서 해당 규칙을 제외했습니다.
- 세션에 돌아왔을 때 어떤 작업을 진행하고 있었는지 파악할 수 있도록, 3턴마다 현재 대화를 fork해 목표, 현재 작업, 결정, 남은 작업을 요약했습니다. 세션 시작 시점의 git 상태와 비교해 변경 파일을 표시하고, 필요한 경우 수동으로 요약을 갱신할 수 있도록 했습니다.
- 모델이 만든 선택지가 사용자 프롬프트로 전달되므로, 전송 전에 보이지 않는 문자를 제거했습니다.

## 해결 및 성과

- 질문 번호와 답을 직접 입력하던 방식을 버튼 선택 후 일괄 전송으로 바꿨습니다.
- 다른 세션에서 돌아왔을 때 대부분 요약만으로 작업을 재개했고, 맥락이 부족한 경우에만 이전 대화를 확인했습니다.
- 합방 파이널 프로젝트 팀원 3명에게 공유했고, 사용한 팀원은 편리하다는 피드백과 함께 지속적으로 사용했습니다.
