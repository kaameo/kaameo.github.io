## 들어가며

Claude Code 옆에 붙는 pane인 sidecar를 하루 동안 0.3.0에서 0.5.0까지 다듬었습니다. 그사이 이슈 20개를 열고 닫았고, 테스트는 35개에서 86개로 늘었습니다.

sidecar를 만든 이유는 단순합니다. Claude가 "a) b) c) 중 무엇으로 할까요?"라고 물을 때마다 답을 손으로 치는 게 번거로웠고, 긴 세션에서는 무엇을 정했고 무엇이 남았는지 놓치기 쉬웠습니다.

이 글은 그 하루의 기록입니다. 무엇을 바꿨는지보다, 바꾸면서 내린 결정과 그 근거를 중심으로 적습니다.

## sidecar가 하는 일

sidecar는 TypeScript hooks 모듈로 만든 Claude Code mod입니다. 대화 옆에 pane 하나를 띄우고, 그 안에 네 섹션을 보여 줍니다.

| 섹션 | 보여 주는 것 | 언제 바뀌나 |
| --- | --- | --- |
| 선택지 | 마지막 답의 선택지와 질문을 버튼으로. 누르면 사용자가 입력한 것처럼 보내집니다. | Claude가 답을 마칠 때마다 |
| 요약 | 세션의 목표, 정한 것, 남은 일, 바뀐 파일 | 5턴마다, 또는 ↻ 갱신 |
| 작업 그림 | 손낸 파일과 모듈을 상자와 선으로 | 요약을 갱신할 때 |
| 로그 | 턴마다 무엇을 물었고 Claude가 무엇을 했는지 한 줄 | 턴이 끝날 때마다 |

로그 한 줄은 턴마다 Haiku가 쓰고, 요약과 작업 그림은 현재 세션을 fork해 만듭니다. 동작하는 모습은 [저장소 README의 데모 GIF](https://github.com/kaameo-lab/sidecar)에 있습니다.

## 하루 동안 바뀐 것

아침에 "sidecar 개선"이라는 막연한 주제로 시작해, 저녁에 0.5.0을 내놓았습니다. 큰 변화는 다섯 덩어리였고, 대부분 직접 써 보고 느낀 불편에서 출발했습니다.

| 단계 | 바뀐 것 | 계기 |
| --- | --- | --- |
| 0.5.0 | 질문 아래 입력창과 포커스 이동, Enter 없이 넘어가도 글 유지, 맨 아래 칸을 "덧붙일 말"로, 보낼 내용 미리보기, 알림 턴 표시 | 실제로 답하다 글이 사라지고, 고른 답이 빠진 채 보내짐 |
| 0.4.0 이후 | README 개편, 데모 GIF, 마켓플레이스 설치 | "plugin으로 설치되어야 한다", "README가 너무 구리다" |
| 0.4.0 | 세션별 저장과 복원, /clear·/resume 처리, 선택지 인식 규칙 추가 | resume하면 로그와 요약이 모두 사라짐 |
| 0.4.0 | git으로 바뀐 파일 추적 | 작업 그림이 비어 있음(Bash로 고친 파일을 모름) |
| 0.4.0 | 선택지·섹션 색 구분, 여백과 구분선 | "색상 구분이 없어서 보기 힘듦" |

태그는 0.4.0과 0.5.0 두 번 찍었고, 두 번 모두 GitHub Release와 CHANGELOG를 함께 남겼습니다.

## 기억에 남는 결정들

### 선택지 인식은 감이 아니라 측정으로 정했다

파서 규칙을 넓히면 놓치는 건 줄지만 오탐이 늘어납니다. 그래서 로컈에 쌓인 대화 기록의 답변 2,352개에 실제 파서를 돌려, 놓친 사례를 하나씩 눈으로 확인했습니다.

- **번호 질문 목록**(`1. 닫을까요?` `2. 만들까요?`): 34개가 새로 잡혔고 모두 진짜 질문이었습니다.
- **"고르라"는 앞 문장 + 숫자 목록**: 앞 두 줄을 보면 "## 워크플로우" 아래 단계 목록까지 걸려서, 바로 앞 한 줄만 보게 좁혔습니다. 새로 잡힌 10개 중 9개가 선택지였습니다.
- **굵은 제목형 선택지**: 숫자 제목(`**1. …**`)은 76개가 걸렸지만 대부분 보고서의 절 구분이었습니다. 문자 제목(`**A. …**`) 4개는 모두 대안이라, 문자 제목만 넣었습니다.

결과적으로 선택지를 찾는 답변은 293개에서 332개로 늘었고, 눈에 띄는 오탐은 늘지 않았습니다. 측정 결과는 이슈 댓글로 남겨, 나중에 규칙을 바꿀 때 근거로 씁니다.

### 보이지 않은 글자는 사용자 이름으로 보내지 않는다

버튼을 누르면 그 글이 사용자가 입력한 것처럼 나갑니다. pane 폭에 잘려 보인 선택지의 전체 문장을 보내면, 사용자가 본 적 없는 말이 사용자 권한으로 나가는 셈입니다.

그래서 잘린 선택지는 키(`b`)만 보냅니다. 이 원칙은 나중에 만든 보낼 내용 미리보기로 이어졌습니다. 보이는 것이 곧 보내지는 것이어야 합니다.

### 바뀐 파일은 도구 호출이 아니라 git에 물어본다

처음에는 Edit·Write 도구 호출만 세었습니다. 마침 그날 Edit 도구가 권한 검사에 막혀 Bash로 파일을 고쳤는데, 작업 그림이 텔 비어 있었습니다.

지금은 세션을 시작할 때 `git stash create`로 작업 트리를 스냅샷해 두고, 턴이 끝날 때마다 그 기준과 비교합니다. 리뷰에서는 가짜 git을 쓰는 테스트로는 드러나지 않는 버그 세 개(rename, 나중에 add한 untracked 파일, 4 MiB 넘는 출력)가 나왔습니다. 커밋 후 보안 리뷰는 파일 이름으로 요약 모델에 지시를 끼워 넣을 수 있다는 점을 짚었습니다.

### 프로세스와 세션은 다르다

pane 상태는 플러그인 reload에는 살아남지만 프로세스가 끝나면 사라집니다. 그래서 세션 id별 스냅샷을 저장해 `claude --resume` 때 복원했습니다.

함정은 `/clear`와 Claude Code 안에서의 `/resume`이었습니다. 둘 다 같은 프로세스에서 세션만 바꾸고, 시작 이벤트는 다시 오지 않습니다. 프로세스 안 `/resume` 복원은 실제로 동작하지 않아 걷어냈고, 걷어내면서 생긴 덮어쓰기 버그는 다른 세션이 찾아내 고쳤습니다.

### 보내기는 누르기 전에 보여야 한다

질문마다 답을 고른 뒤 맨 아래 칸에 글을 쓰고 보내면, 고른 답은 빠지고 그 글만 나갔습니다. 그 칸은 "답 전체를 대신 쓰는 칸"으로 만들어져 있었기 때문입니다.

답 전체는 Claude Code 입력창에서 쓰면 되니, 이 칸은 고른 답 아래에 붙는 "덧붙일 말"로 바꿨습니다. 그리고 마지막 질문 아래에 점선을 긋고, 보낼 글을 테두리 상자로 미리 보여 줍니다.

## Claude Code와 일한 방식

변경 하나하나가 같은 고리를 돌았습니다. 질문으로 정하고, 이슈로 남기고, 테스트부터 쓰고, 써 보고 다시 고치는 순서입니다.

&#91;embedded content: 작업 고리 · 5단계, 사용에서 다시 질문으로\]

다섯 단계를 하루에 여러 바퀴 돌았고, 바퀴마다 시작은 실제로 써 보며 느낀 불편이었습니다.

1. **질문 라운드로 정하기**: Claude가 결정해야 할 것을 `Q1 - …` 형식으로 묻고, 질문마다 추천 답을 붙였습니다. 대부분 "추천대로"로 답했고, 이 답은 sidecar 버튼으로 눌렀습니다.
2. **이슈로 남기기**: 합의한 내용을 수용 기준까지 담아 GitHub 이슈로 열었습니다. 선행 관계가 있는 이슈는 GitHub의 의존 관계로 묶었습니다.
3. **테스트부터 쓰기**: 실패하는 테스트를 먼저 보고 구현했습니다. 테스트가 처음부터 통과하면, 고치기 전 코드에서 정말 실패하는지 되돌려 확인했습니다.
4. **두 축으로 리뷰하기**: 큰 변경은 표준(코드 규칙)과 스펙(이슈 내용) 리뷰를 따로 돌렸습니다. git 경계 사례 버그는 이 단계에서 나왔습니다.
5. **써 보고 스크린샷으로 돌려주기**: reload해서 직접 쓰고, 이상한 화면을 찍어 넘겼습니다. "✎ 버튼이 깨져 보인다", "고른 답이 빠진다" 같은 문제는 테스트가 아니라 이 단계에서 나왔습니다.

잘 안 된 것도 있습니다. 테스트 키트로는 포커스 이동을 검증할 수 없어서, 그 동작은 손으로만 확인했습니다. 파일 수정 도구가 권한 검사에 막히거나, 릴리스 태그 push가 거부돼 직접 명령을 친 적도 있습니다.

## 배운 점과 다음 계획

가장 크게 배운 건, 직접 써 본 한 번이 테스트 여러 개보다 많은 걸 알려준다는 점입니다.

- **휴리스틱은 실제 데이터로 재기**: 규칙을 넓힐 때마다 실제 답변에 돌려 보지 않았다면, "숫자 제목도 선택지"라는 오탐 76개짜리 규칙을 넣었을 겁니다.
- **프로세스와 세션을 구분하기**: "세션이 끝난다"와 "프로세스가 끝난다"는 다른 사건입니다. 상태를 어디에 두는지는 이 차이로 정해집니다.
- **테스트가 보지 못하는 것을 알기**: 포커스, 터미널이 다시 그릴 때의 정렬 같은 건 테스트 키트가 보여주지 않습니다. 그런 건 커밋 메시지에 "손으로 확인함"이라고 분명히 남겼습니다.

다음으로는 영어 README와 플러그인 아이콘을 준비해, 플러그인 디렉터리에 등록할 계획입니다.

### 설치

Claude Code 안에서 한 줄로 설치합니다.

```
/plugin install sidecar --marketplace kaameo-lab/sidecar
```

저장소는 [github.com/kaameo-lab/sidecar](https://github.com/kaameo-lab/sidecar)입니다. pane 문구와 선택지 인식은 한국어 답변 기준입니다.
